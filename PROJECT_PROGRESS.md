## 1. Project Architecture Discovered

### Frontend Entry Points & Configuration
- **Entry File:** `src/main.jsx` mounts `App.jsx` with `BrowserRouter`.
- **Package Config:** `package.json` contains React 19.2.8, React Router DOM 7.18.4, Supabase JS 2.117.2, Tailwind CSS 3.4.19, Vite 8.3.0.
- **Vite Config:** `vite.config.js` with `@vitejs/plugin-react`.
- **CSS System:** `src/index.css` contains custom design tokens, buttons (`.btn`, `.btn-primary`, `.btn-secondary`, `.btn-sm`, `.btn-lg`), cards (`.card`, `.fintech-card`), inputs (`.input`, `.input-error`), tables (`.table-wrapper`, `.table`), and alert boxes (`.alert-info`, `.alert-error`, `.alert-success`, `.alert-warning`).
- **Formatting Utilities:** `src/utils/formatters.js` provides `formatCurrency`, `formatDate`, `formatDateTime`, `getIpoStatusBadgeClass`, `getIpoStatusLabel`, `formatProfitLoss`, `parseNumericFromImport`.

### Authentication & Authorization Architecture
- **Supabase Client:** `src/lib/supabaseClient.js` initialized via `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
- **Auth Context:** `src/context/AuthContext.jsx` manages session, user profile, `isAdmin: profile?.role === 'admin'`, `isAuthenticated: !!session?.user`.
- **Route Guards:** `src/routes/RouteGuards.jsx`:
  - `ProtectedRoute`: requires `isAuthenticated`, redirects pending users to `/pending-approval`.
  - `AdminRoute`: requires `isAuthenticated` and `isAdmin`.
  - `PublicOnlyRoute`: redirects authenticated users to their respective dashboards.
- **User Roles:** `user` and `admin` stored in `public.profiles.role`.
- **Database Function:** `public.is_admin()` is a `SECURITY DEFINER` function checking `profiles.role = 'admin'` for `auth.uid()`.

### Existing Database Schema (Supabase)
- **`public.profiles`**: `id` (UUID, FK auth.users), `username`, `full_name`, `email`, `role` ('user'|'admin'), `is_active`, `is_approved`, `approval_status`, timestamps.
- **`public.ipos`**:
  - `id` UUID PRIMARY KEY DEFAULT gen_random_uuid()
  - `ipo_code` TEXT UNIQUE NOT NULL (auto-generated by trigger `trg_generate_ipo_code` as `IPO` + sequence)
  - `ipo_name` TEXT NOT NULL
  - `ipo_price` NUMERIC(15,2) NOT NULL CHECK (ipo_price > 0)
  - `start_date` DATE
  - `end_date` DATE
  - `status` TEXT NOT NULL DEFAULT 'DRAFT' CHECK (status IN ('DRAFT','OPEN','CLOSED','PROCESSING','COMPLETED','CANCELLED'))
  - `overall_profit` NUMERIC(15,2)
  - `created_by` UUID REFERENCES public.profiles(id)
  - `completed_at` TIMESTAMPTZ
  - `created_at`, `updated_at` TIMESTAMPTZ
- **`public.ipo_participations`**: `id`, `ipo_id`, `user_id`, `participation_type` ('INVESTOR'|'ACCOUNT_HOLDER'), `application_number`, `investor_user_id`, `amount_contributed`.
- **`public.ipo_results`**: `id`, `participation_id`, `applied`, `allotted`, `lots`, `applied_from`, `refund_amount`, `profit_amount`, `tax_amount`, `final_settlement_amount`, `result_status`.
- **`public.ipo_result_imports`**: `id`, `ipo_id`, `imported_by`, `source_type`, `total_rows`, `status`, `error_log`.
- **`public.user_ipo_profits`**: `id`, `ipo_id`, `user_id`, `investor_share`, `account_holder_share`, `total_profit`.

### Existing IPO Creation & Publishing Flow
1. Admin navigates to `/admin/ipos/create`.
2. Admin enters: IPO Name, IPO Price, Start Date, End Date.
3. Form invokes `createIpo(...)` in `src/services/ipoService.js`.
4. IPO is inserted into `public.ipos` with status `'DRAFT'`, and trigger assigns `ipo_code` (`IPO1001`...).
5. Admin is redirected to `/admin/ipos/:ipoId`.
6. On `/admin/ipos/:ipoId`, admin sees `→ Open` button (`STATUS_TRANSITIONS['DRAFT'] = ['OPEN', 'CANCELLED']`).
7. Admin clicks `→ Open`, invoking `updateIpoStatus(ipoId, 'OPEN')`.
8. Once status is `'OPEN'`, the IPO becomes visible to public visitors on `/ipos` and authenticated users on `/user/ipos`.

## 2. Identified Gaps & Requirements for Enhancement

1. **JSON Import Interface:** Currently only manual 4-field creation exists. An "Import JSON" tab is needed with JSON editor, paste, validation, and rich preview.
2. **Canonical Data Model:** Full support for all 13 sections from IPO Gyani format:
   - `ipo_details`, `ipo_dates`, `gmp`, `subscription`, `reservation_quota`, `issue_details`, `lot_size_details`, `kpi`, `financials`, `company_details`, `company_contact`, `official_documents`, `faq`.
3. **Database Persistence:** New relational table `public.ipo_details` linked 1-to-1 to `public.ipos` to store structured columns for fast querying plus JSONB for detailed sections and `raw_json` for complete auditability.
4. **Shared Creation Service:** Atomic creation function (PostgreSQL RPC `create_ipo_with_details`) to safely insert `ipos` and `ipo_details` in a single transaction without orphaned records.
5. **Public Detail Page:** Currently NO public `/ipos/:ipoId` detail page exists. Public visitors can only see summary cards on `/ipos`. We must create `/ipos/:ipoId` with all 13 sections.
6. **Apply IPO Access Control:** On `/ipos/:ipoId`, public visitors see rich details but no Apply button (instead "Log In to Apply"); authenticated users see "Apply for IPO" linking to `/user/apply/:ipoId`.
7. **Admin Detail Page Enhancement:** Display the rich imported details on `/admin/ipos/:ipoId` so admins can inspect the full prospectus, GMP, subscription, financials, etc.

## 4. Final Verification & Delivery Report

### 1. Features Implemented
- **Dual-Mode IPO Creation:** Existing manual 4-field creation workflow is preserved 100% while offering an "Import IPO JSON" tab.
- **Robust JSON Parsing & Syntax Diagnostics:** Safe JSON parser identifies syntax errors with exact line and column numbers and diagnostic hints (missing comma, trailing comma, quotes).
- **Canonical IPO Gyani Model Mapping:** Full mapping and normalization for all 13 sections: `ipo_details`, `ipo_dates`, `gmp`, `subscription`, `reservation_quota`, `issue_details`, `lot_size_details`, `kpi`, `financials`, `company_details`, `company_contact`, `official_documents`, `faq`.
- **Zero & Null Precision Preservation:** Respects numeric zeros (e.g. `company_proceeds: 0`), boolean `false` (e.g. `fresh_issue: false`), `null` values without replacing them with 0, and relative strings like `"2m ago"` without converting them into numbers.
- **Complete Editable Preview:** 16 structured preview sections in an interactive tabbed interface before saving to database. Inline quick-edit controls allow editing key fields (name, price, dates).
- **Financial Statement Comparison Table:** Dynamically pivots fiscal year financial metrics (`total_income`, `net_profit`, `ebitda`, `borrowings`, `roe`, `roce`, `assets`) into multi-column year-over-year comparison tables.
- **Unofficial GMP Advisory Disclaimer:** Clearly distinguishes unofficial GMP estimates from official exchange data with explicit advisory notices.
- **Atomic Database Persistence:** PostgreSQL RPC `public.create_ipo_with_details` safely creates `ipos` and `ipo_details` in a single transaction with automatic fallback.
- **Public IPO Details Route (`/ipos/:ipoId`):** Public visitors can explore published IPO details with responsive layout across mobile and desktop.
- **Role-Aware Apply IPO Action:** Authenticated users see "Apply for IPO" (linking to `/user/apply/:ipoId`), while public visitors see "Log In to Apply" (linking to login with redirect).
- **Admin Details Enhancement:** Admin IPO detail view (`/admin/ipos/:ipoId`) includes a dedicated "Prospectus Details" tab and a quick link to the public detail page.
